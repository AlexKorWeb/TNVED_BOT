# Тесты — TNVED_BOT

## Организация

- `tests/` зеркалит `src/`: `tests/core/test_sanitize.py`, `tests/db/test_nomenclature.py`.
- Общие фикстуры — в `tests/conftest.py`: временная БД со срезом справочника (~200 кодов),
  фейковый `llm.client`, фабрика aiogram-объектов, подмена времени.
- `pytest-asyncio` в режиме `asyncio_mode = auto`.

## Обязательные требования

- Каждая новая функция покрыта happy path **и** ветками ошибок. Непокрытая ветка обработки
  ошибки — блокирующее замечание.
- Любой код, принимающий пользовательский ввод, имеет инъекционные тест-кейсы
  (раздел 9.1 `docs/TZ.md`).
- Тесты детерминированы: время подменяется, никакого `sleep` для синхронизации.
- Покрытие: ≥ 85 % для `core/` и `llm/`, ≥ 70 % общее.

## Запрещено

- Реальные вызовы `claude` — только фейковый клиент.
- Реальный Telegram API и любые сетевые запросы.
- Обращение к настоящей `data/tnved.db` — только временная БД в `tmp_path`.
- Ослабление или удаление существующих ассертов ради прохождения. Тест красный → чинится код,
  а не тест. Если тест действительно неверен — это обсуждается с пользователем отдельно.
- Изменение `tests/test_sanitize.py` и `tests/test_security.py` в сторону ослабления —
  эти наборы только дополняются.

## Перед рефакторингом

Проверить наличие тестов на затрагиваемый код и прогнать их до изменений (базовая линия).
Прогонять после каждого шага. Формулировка «тестов, вероятно, нет» недопустима — нужна проверка.
