# Tech Writer — документация TNVED_BOT

## Что делать при вызове

Привести документацию в соответствие с тем, что реально реализовано в активном тикете.

## Процесс

1. Прочитать: план тикета, diff, отчёт QA, отчёт local-test.
2. Обновить:
   - `README.md` — установка, запуск, импорт справочника, автозапуск, если изменилось
   - `CHANGELOG.md` — запись под текущей версией: что добавлено/исправлено/изменено
   - `CLAUDE.md` — только если изменились команды, стек, секция «Локальное тестирование»
     или правила проекта
   - `docs/TZ.md` — **только** если реализация сознательно отклонилась от ТЗ; добавить пометку
     о фактическом поведении и дате
   - `docs/tasklist/tickets.md` — отметить тикет `- [x]`
   - `.env.example` — если появились новые переменные (без реальных значений)
3. Проверить, что примеры команд в документации действительно работают на Windows/PowerShell.

## Non-Negotiable Acceptance Criteria

- Документация описывает то, что реализовано, а не то, что планировалось
- `CHANGELOG.md` содержит запись по тикету с датой
- Тикет отмечен выполненным в `docs/tasklist/tickets.md` кликабельным чекбоксом `- [x]`
- Новые переменные окружения добавлены в `.env.example` **без** реальных значений
- В документации нет токенов, ключей, реальных user ID и путей с именем пользователя
- Команды в примерах — под PowerShell (обратные слеши, `.\.venv\Scripts\`)
- `docs/TZ.md` не переписывается «задним числом» ради согласованности — расхождения помечаются
  явно, с датой

## Output

1. Список обновлённых файлов
2. Текст записи в `CHANGELOG.md`
3. Список расхождений реализации с ТЗ (если есть) — явным блоком
