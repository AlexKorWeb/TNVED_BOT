# /full-cycle — полный цикл разработки тикета

Восемь фаз с паузами. Не переходи к следующей фазе без явного «ок» пользователя.

```text
analyst → researcher → planner → implementer → reviewer → qa → local-test → tech-writer
```

## Предусловие

`docs/.active_ticket` содержит номер тикета. Если нет — спроси у пользователя и запиши.

## Фазы

| # | Фаза | Агент / команда | Артефакт | Условие перехода |
|---|---|---|---|---|
| 1 | Требования | `analyst` | `docs/prd/<id>.md` | пользователь подтвердил PRD |
| 2 | Исследование | `researcher` | `docs/research/<id>.md` | существующие тесты прогнаны, базовая линия зафиксирована |
| 3 | План | `planner` | `docs/plan/<id>.md` | **пользователь явно подтвердил план** |
| 4 | Реализация | `implementer` | код + тесты + CHANGELOG | `ruff`/`mypy`/`pytest` зелёные |
| 5 | Ревью | `reviewer` | список замечаний | нет блокирующих замечаний |
| 6 | Автотесты | `qa` | `reports/qa/<id>.md` | вердикт `PASS` |
| 7 | **Локальный запуск** | `/local-test` | `reports/qa/local-test-<дата>.md` | ✅ бот стартовал и ответил |
| 8 | Документация | `tech-writer` | README/CHANGELOG/тикет отмечен | — |

## Правила остановки

- **Фаза 3 → 4:** без явного подтверждения плана код не пишется. Это жёсткое правило.
- **Фаза 5:** есть блокирующие замечания → возврат к фазе 4 с их списком.
- **Фаза 6:** вердикт `FAIL` → возврат к фазе 4 с шагами воспроизведения.
- **Фаза 7:** локальный запуск упал → **pipeline останавливается**, возврат к фазе 4 с логом
  ошибки. Пропустить этот шаг или объявить его успешным без реального запуска нельзя.
- На любой фазе: обнаружено, что план неверен → остановись и скажи пользователю,
  не «дорабатывай на ходу».

## После фазы 8

1. Покажи итоговый diff.
2. Спроси пользователя про коммит. Коммит и push — только по явной просьбе.
3. Предложи следующий тикет из `docs/tasklist/tickets.md`.
