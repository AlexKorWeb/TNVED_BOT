## Дефекты, найденные интеграционными тестами

Модульные тесты их не видели — каждый слой по отдельности выглядел исправным.

### 1. Активация приглашений не работала вообще — критично

`CommandStart(deep_link=False)` **не срабатывает** на `/start КОД`: фильтр возвращает `False`
(проверено экспериментом на этой версии aiogram). Апдейт молча не доходил ни до одного
обработчика. Это единственный способ пригласить человека, не спрашивая его Telegram ID, —
то есть основной сценарий подключения новых пользователей был нерабочим.

### 2. Глобальный обработчик ошибок ничего не ловил — критично

Зарегистрированный отдельным дочерним роутером, он перехватывает только ошибки **своих**
обработчиков. Сбои в командах, тексте и кнопках проходили мимо: пользователь не получал
ни сообщения, ни `error_id`. Перенесён на диспетчер.

### 3. Роутеры-синглтоны делали бота непроверяемым

Модульный `router = Router(...)` нельзя подключить ко второму диспетчеру — тесты падали
с `Router is already attached`. Переведено на фабрики `build_router()`.

## Дефекты, найденные при живой проверке автозапуска

### 4. Скрипты `.ps1` ломались у пользователя из-за кодировки

PowerShell 5.1 читает `.ps1` как ANSI, если нет BOM. Кириллица в сообщениях превращалась
в мусор и **ломала разбор скрипта** — `install_autostart.ps1` падал с
`A positional parameter cannot be found`. Все скрипты пересохранены в UTF-8 с BOM.

### 5. Планировщик не перезапускал упавшего бота

`RestartCount 3 / RestartInterval 1 min` не сработали: задача завершалась с
`LastTaskResult 0xFFFFFFFF`, но повтор не запускался — бот оставался лежать 150 с наблюдения.
Перезапуск перенесён в сам `run_bot.ps1`: цикл с растущей паузой, без перезапуска на кодах
0 (штатная остановка), 2 (ошибка конфигурации) и 3 (уже запущен). Проверено — поднимается
за ~10 с.

### 6. Скрипт остановки убил собственную оболочку

Поиск `CommandLine -like "*run_bot.ps1*"` совпал с сессией, из которой скрипт был запущен:
её командная строка содержала это имя. По той же причине под нож попал бы редактор с открытым
файлом. Теперь проверяется признак запуска (`-File <полный путь>`, `-m tnved_bot`) и
исключается `$PID`. Опасная рекомендация убрана и из `CLAUDE.md`.

## Аудит безопасности

`tests/test_security.py` — 52 проверки сквозного поведения, а не отдельных слоёв:

- **20 инъекций** прогоняются через весь пайплайн. Ни одна не меняет поведение, не рвёт
  структуру промта и не приводит к выдаче кода вне справочника.
- **100 выдуманных ответов модели** (`9000000000`…`9000000099`) — ни один не дошёл до
  пользователя; каждый выданный код сверен с БД.
- Текст пользователя всегда внутри одного блока `<user_data>` — проверяется по фактическому
  промту, а не по коду.
- SQL- и FTS-метасимволы: справочник цел после каждого запроса.
- Разметка и ссылки из ответа модели вырезаются до формирования сообщения.
- Path traversal при удалении фотографий невозможен.
- В `src/` нет ни ключей провайдеров, ни обращений к `api.anthropic.com` / `api.openai.com`.

Отдельно проверено в `test_photo_store.py`: EXIF (включая геолокацию) срезается ре-энкодом,
polyglot-нагрузка, приклеенная к валидному JPEG, уничтожается, декомпрессионная бомба
(9000×9000 px) отклоняется, имя файла — только UUID4.

`test_users.py`: 10 параллельных активаций одного кода приглашения → доступ получает **ровно
один**. Схема «прочитал → проверил → записал» пропустила бы всех.

`test_janitor.py`: догоняющая очистка при старте удаляет фото, просроченные за время простоя
компьютера; занятый файл не останавливает остальные задачи; заблокировавший бота пользователь
не ломает джанитор.

## Известные ограничения

- Классификация занимает 12–18 с: два обращения к ИИ. Это цена того, что бытовое слово
  переводится на язык справочника.
- Модель может уверенно выбрать неверный, но существующий код. Смягчается альтернативами,
  обоснованием и дисклеймером; кнопки 👍/👎 копят материал для правки промтов.
- Фотография не классифицируется без подтверждения описания пользователем — это осознанно:
  иначе код брался бы из того, что бот «разглядел», без возможности поправить.
