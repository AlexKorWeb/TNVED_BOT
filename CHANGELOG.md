## [1.0.0] — 2026-08-07

Бот собран целиком и работает: 20 тикетов закрыты, 426 тестов, покрытие 87 %.
Отчёты: [T-004…T-008](reports/qa/T-004-T-008.md), [T-009…T-019](reports/qa/T-009-T-019.md).

### Added

- Telegram-бот на aiogram 3: классификация по описанию и по фотографии, уточняющие вопросы
  кнопками (до 3 раундов), таймаут диалога 30 минут.
- Управление доступом: whitelist в БД, одноразовые коды приглашений на 24 часа,
  команды `/users`, `/adduser`, `/deluser`, `/invite` — без перезапуска бота.
- Приём фотографий с обязательным ре-энкодом в JPEG, TTL 48 часов и догоняющей очисткой
  после простоя компьютера.
- Лимиты обращений в БД, журнал событий без текстов пользователей, служебные команды
  `/health`, `/stats`, `/code`, `/version`, `/forget`.
- Автозапуск через планировщик задач с надзорным перезапуском.
- Сводный аудит безопасности: 20 инъекций сквозь весь пайплайн, 100 выдуманных ответов
  модели, path traversal, SQL/FTS-метасимволы.

### Fixed

- **`CommandStart(deep_link=False)` не срабатывает на `/start КОД`** — активация приглашений
  не работала вообще. Найдено интеграционным тестом.
- **Глобальный обработчик ошибок ничего не ловил**: на дочернем роутере он перехватывает
  только собственные ошибки. Перенесён на диспетчер.
- **Скрипты `.ps1` ломались из-за кодировки**: PowerShell 5.1 читает их как ANSI без BOM,
  кириллица рушила разбор скрипта.
- **Планировщик не перезапускал упавшего бота** — перезапуск перенесён в `run_bot.ps1`.
- **Скрипт остановки убивал собственную оболочку**: поиск процессов по подстроке совпадал
  с сессией, из которой был запущен.

## [Unreleased]

### Added — T-020…T-027 таможенная справка и качество подбора

- **Пошлина и НДС** в ответе — у основного кода и у **каждой альтернативы**. Ставка берётся
  из локального справочника, НДС — из внешней справки; без интернета ставка всё равно видна.
- **Разрешительные документы и техрегламенты** по коду. Различаются обязательные
  («необходимые для ввоза») и условные («могут потребоваться»): на этой разнице строится
  подбор варианта без разрешительной документации.
- **Маркировка «Честный знак»** — локальная таблица `customs/marking.csv` (149 правил).
  Ответ даётся всегда, в том числе отрицательный: молчание пользователь прочитал бы как
  «маркировка не нужна», а таблица префиксов такого утверждения не позволяет.
- **Блок «рядом есть ставка ниже»** — соседние коды той же товарной позиции с меньшей
  пошлиной, с явным предупреждением, что код определяется свойствами товара, а не ставкой.
- **Обучение на исправлениях**: 👎 → бот просит верный код → пара «запрос → код» ложится
  в `corrections` и попадает и в промт, и в список кандидатов при похожем запросе.
  `/corrections` показывает накопленное.
- **Примеры реальных деклараций** как подсказка, когда модель не уверена: обезличенная
  графа 31 называет товар бытовым языком («КОФЕВАРКА»), которого в номенклатуре нет.
- **Ссылка-приглашение** `https://t.me/бот?start=КОД` — код больше не вводится руками.
  Вторым сообщением приходит готовое приглашение для пересылки.
- **Рассылка** `/broadcast` и кнопка в панели: предпросмотр → подтверждение → отправка
  с ограничением темпа и отчётом. Заблокировавший бота не срывает рассылку остальным.
- **Запуск без консольного окна**: задача планировщика вызывает `wscript.exe` с
  `scripts/run_hidden.vbs`. `-WindowStyle Hidden` окно всё равно создавал.
- Схема БД v3: `code_reference` (кеш справки, TTL 30 дней) и `corrections`.
- Новых зависимостей нет: `aiohttp` уже стоит как зависимость `aiogram`.
- Тестов стало 512.

### Security — T-020

- Ответ чужого сайта обрабатывается как недоверенные данные: код в URL проверяется на
  «ровно десять цифр» (он приходит из ответа модели), хост зафиксирован, конечный адрес
  после редиректов сверяется, размер и время ответа ограничены, все поля обрезаются по
  длине и экранируются при выводе.
- Код из таблицы исправлений всё равно проходит `verify_code` — испорченная запись не даёт
  способа протащить несуществующий код.

### Fixed — найдено на живой проверке

- **В «ставку ниже» попадали посторонние коды.** Кофеварке предлагались нагревательные
  блоки противообледенительных систем воздушных судов: формально сосед по товарной позиции
  8516 и дешевле. Теперь код обязан быть либо найден поиском по описанию, либо делить
  субпозицию с выбранным.
- **И позиции «части».** У них ставка почти всегда ниже, и предложить их для целого
  изделия — значит подсказать классическое недостоверное декларирование.
- **Ставка показывалась из внешнего источника, а разница в п.п. считалась от локального
  справочника.** При расхождении источников числа в ответе не сошлись бы. Источник для
  показа и для арифметики теперь один.
- **Обработчик черновика рассылки удваивал расход лимита.** `SkipHandler` из тела
  обработчика прогонял цепочку `auth → ratelimit → logging` второй раз; проверка перенесена
  в фильтр, который отрабатывает до внутренних middleware.

### Fixed

### Added — T-003 Импорт справочника ТН ВЭД

- `xlsx.py` — потоковый читатель XLSX на stdlib (`zipfile` + `ElementTree`), без `openpyxl`.
  Ячейки разбираются по ссылке `r="C2"`: пустые ячейки в XLSX отсутствуют в разметке, и без
  этого разреженная строка съехала бы на колонку влево.
- `importer.py` — разбор CSV/XLSX, поиск колонок по синонимам заголовков, разбор иерархии
  из наименования, валидация с отчётом об отклонённых строках (номер + причина).
- `db/nomenclature.py` — версии справочника, атомарный импорт, откат, `verify_code`
  (только активная версия) и пересборка FTS-индекса при переключении.
- `scripts/import_nomenclature.py` — CLI: импорт, `--force`, `--rollback`, `--list`.
- `tests/fixtures/nomenclature_sample.csv` — срез из 207 реальных кодов.
- Справочник загружен: **13 293 кода, актуальность 07.08.2026, импорт за 1.1 с, 0 отклонений**.
  `smoke_check` даёт 5 зелёных из 5.
- Тестов стало 142. Отчёт: [reports/qa/T-003.md](reports/qa/T-003.md).

### Security — T-003

- **Разбор XML защищён от billion laughs.** Проверено на этой версии Python: XXE
  `ElementTree` отбивает сам, а внутренние сущности разворачивал — архив на 600 КБ мог
  развернуться в гигабайты. Закрыто запретом любого DTD (в настоящем XLSX его не бывает)
  плюс ограничением на размер распакованной записи. Оба случая покрыты тестами,
  `defusedxml` не понадобился.

### Added — T-002 Слой БД

- `db/schema.sql` — 9 таблиц: справочник и его версии, FTS5-индекс, `allowed_users`,
  `invite_codes`, `photos`, `sessions`, `audit_log`, `usage_counters`. Единственность
  активной версии справочника обеспечена уникальным частичным индексом, состояния и
  перечисления — `CHECK`-ограничениями.
- `db/engine.py` — соединение `aiosqlite` с WAL, `foreign_keys=ON`, повторами при
  `database is locked` (0.1/0.3/0.9 с), транзакциями, горячим бэкапом и восстановлением
  после повреждения файла.
- `db/audit.py` — журнал событий; отказывается принимать поля с текстом пользователя,
  вместо содержимого — `text_digest()`.
- `db/counters.py` — счётчики лимитов в БД (переживают перезапуск), инкремент через
  `UPSERT ... RETURNING` без гонок.
- `db/photos.py`, `db/sessions.py` — учёт фото с обязательным TTL и состояние диалогов.
- `clock.py` — единая точка времени (UTC), чтобы тесты TTL могли подменять его.
- БД подключается при старте: событие `bot_started` теперь содержит версию схемы.
- Тестов стало 76, покрытие 93 %. Отчёт: [reports/qa/T-002.md](reports/qa/T-002.md).

### Fixed — T-002

- **Восстановление после повреждения БД падало с `PermissionError`:** соединение не
  закрывалось при ошибке открытия, и Windows не давал переименовать битый файл.
  Повреждение вылезает уже на первой `PRAGMA`, когда объект соединения создан.
- **Бэкапы внутри одной секунды перезаписывали друг друга** — в имя добавлены миллисекунды,
  иначе хранилось меньше копий, чем заказано.

### Added — T-001 Каркас проекта, конфигурация, логирование

- `config.py` — конфигурация на `pydantic-settings`, 34 переменные, валидация при старте.
  `ADMIN_USER_IDS` разбирается из CSV собственным валидатором: составные типы
  `pydantic-settings` читает из окружения как JSON, и `ADMIN_USER_IDS=123,456` упал бы.
  Ошибки конфигурации выводятся человекочитаемым текстом на русском, без traceback.
- `logging_setup.py` — `structlog` + JSON + ротация 10 МБ × 5, маскирование секретов
  на двух уровнях (процессор structlog и `MaskingFormatter` на handler'ах).
- `core/errors.py` — иерархия `TnvedError` с полем `user_message`.
- `lockfile.py` — защита от второй копии через блокировку ОС (`msvcrt` / `fcntl`).
  Лок и PID разнесены по разным файлам: `bot.lock` и `bot.pid`.
- `__main__.py` — старт, graceful shutdown по SIGINT/SIGTERM/SIGBREAK, коды выхода
  0/1/2/3.
- `scripts/smoke_check.py` — проверка запущенного бота (процесс, `claude`, лог, диск,
  справочник).
- `pyproject.toml` — ruff (14 наборов правил), mypy (strict для `core/` и `llm/`), pytest.
- 44 теста, покрытие 93 %. Отчёт: [reports/qa/T-001.md](reports/qa/T-001.md).

### Fixed — T-001 (найдено тестами и локальной проверкой)

- **Утечка токена в лог из URL:** `\b` в шаблоне маскирования не срабатывал на
  `.../bot<token>/getMe` — именно в таком виде aiogram логирует запросы к Telegram API.
- **Утечка токена в лог из traceback:** `logger.exception()` дописывал traceback мимо
  процессоров structlog. Добавлен `MaskingFormatter` на уровне handler'ов.
- **PID был нечитаем при живом боте:** обязательная блокировка Windows не давала
  прочитать `bot.lock`, где лежал PID. Файлы разделены.
- **Устаревший PID мог привести к убийству чужого процесса:** `bot.pid` удаляется при
  штатной остановке, перед `Stop-Process` требуется проверка `CommandLine`.
- **`already_running` логировался как ERROR** — понижено до WARNING: это штатный исход
  при автоперезапуске планировщиком.
