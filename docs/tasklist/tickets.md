# Тикеты реализации TNVED_BOT

Источник требований — [[../TZ|docs/TZ.md]]. Порядок тикетов = порядок реализации:
каждый следующий опирается на предыдущие. Не браться за тикет, пока не закрыты его зависимости.

Работа по тикету: `/full-cycle` (analyst → researcher → planner → implementer → reviewer → qa →
local-test → tech-writer). Номер активного тикета — в `docs/.active_ticket`.

**Оценки** — грубые, в человеко-часах для ориентира по размеру, а не обязательство.

## Этап 1 — Фундамент (T-001 … T-004)

Цель этапа: есть работающий справочник ТН ВЭД в SQLite и функция, которая по описанию находит
кандидатов. Бота ещё нет — проверка через pytest и CLI.

### - [x] T-001 — Каркас проекта, конфигурация, логирование

**Зависимости:** нет · **Оценка:** 3 ч · **Готово 2026-08-07** ·
Отчёт: [[../../reports/qa/T-001|reports/qa/T-001.md]]

**Что делать**

- `requirements.txt` с точными версиями (`aiogram`, `aiosqlite`, `pydantic`, `pydantic-settings`,
  `Pillow`, `apscheduler`, `structlog`) + dev-зависимости (`pytest`, `pytest-asyncio`,
  `pytest-cov`, `ruff`, `mypy`)

**Acceptance criteria**

- [ ] Отсутствие `BOT_TOKEN` или пустой `ADMIN_USER_IDS` → понятное сообщение на русском, не traceback
- [ ] `ADMIN_USER_IDS=123,456` разбирается корректно (не через JSON); нечисловое значение → фатальная

- [ ] Вторая копия процесса завершается с сообщением о занятом локе, первая продолжает работать
- [ ] `BOT_TOKEN` в логах замаскирован (`****`) — проверено тестом
- [ ] `ruff check src tests` и `mypy src` — чисто

### - [x] T-003 — Импорт справочника ТН ВЭД

**Зависимости:** T-002 · **Оценка:** 6 ч · **Готово 2026-08-07** ·
Отчёт: [[../../reports/qa/T-003|reports/qa/T-003.md]]

**Источник подтверждён и уже лежит в проекте:** `data/nomenclature/tnved_tws_2026-08-07.xlsx`
(13 293 кода уровня 10, 0 дубликатов, 96 групп, иерархия в наименовании через `🠺`).
Разбор источника и его ограничения — [[../research/nomenclature-sources|docs/research/nomenclature-sources.md]].

**Что делать**

- `scripts/import_nomenclature.py`: чтение CSV/XLSX из `data/nomenclature/` → конфигурируемый
  маппинг колонок → валидация (код 2/4/6/8/10 цифр, непустое наименование) → построение
  `parent_code` и `name_full` (наименование с контекстом родителей) → транзакционная запись новой
  версии → пересборка FTS-индекса → атомарное переключение `is_active`
- Специфика источника TWS: данные на **второй** вкладке (`ТНВЭД`), дата актуальности —
  с первой (`Система TWS`); разделитель иерархии `🠺` (U+1F83A) → ` / `; последний сегмент пути →
  `name`, полный путь → `name_full`; колонка `Тариф` — в отдельное поле (задел под v2);
  колонку `Подробности` отбрасывать; `unit` и `notes` остаются `NULL` (в источнике их нет)
- Отчёт импорта: строк прочитано / записано / отклонено, с причинами отклонения
- Откат: `--rollback` переключает `is_active` на предыдущую версию, не удаляя данные
- Срез справочника (~200 кодов) в `tests/fixtures/nomenclature_sample.csv`

**Acceptance criteria**

- [ ] Импорт полного справочника проходит за разумное время и сообщает статистику
- [ ] Битые строки не срывают импорт: отклоняются с указанием номера строки и причины
- [ ] При падении на середине активная версия остаётся прежней (транзакция откатывается)
- [ ] `--rollback` возвращает предыдущую версию, данные не теряются
- [ ] `sha256` файла-источника и дата импорта записаны в `nomenclature_version`
- [ ] Повторный импорт того же файла определяется по `sha256` и требует явного `--force`

### - [x] T-004 — Поиск кандидатов (FTS5) и верификация кода

**Зависимости:** T-003 · **Оценка:** 5 ч

**Что делать**

- `src/tnved_bot/db/nomenclature.py`:
  - `search(query, limit)` — токенизация запроса по whitelist `[а-яa-z0-9]`, удаление стоп-слов,
    экранирование спецсимволов FTS5 (`" * : ^ - NEAR`), приоритетный `AND`-запрос + дополняющий
    `OR`, ранжирование `bm25()` с бо́льшим весом `name`
  - деградация: 0 совпадений → поиск `LIKE` по `name` → пусто → пустой список (без исключения)
  - `verify_code(code)` — существует ли код в **активной** версии; возвращает официальное
    наименование, `unit`, родительские позиции
  - `get_code_info(code)` — для команды `/code`
- Возврат до 40 кандидатов уровня 10 + родительские позиции уровня 4 и 6 для контекста

**Acceptance criteria**

- [ ] «кофеварка капельная бытовая» находит `8516 71 000 0` в первой десятке кандидатов
- [ ] Спецсимволы FTS5 в запросе не ломают поиск и не вызывают исключения (тест с `" * ^ NEAR -`)
- [ ] `verify_code` для несуществующего кода возвращает `None`, а не исключение
- [ ] `verify_code` не находит код из неактивной версии справочника
- [ ] Запрос из одних стоп-слов → пустой список, без падения
- [ ] Поиск по срезу из 200 кодов отрабатывает < 50 мс

## Этап 2 — ИИ-слой (T-005 … T-008)

Цель этапа: по строке описания получается верифицированный код с уверенностью. Всё ещё без бота.

### - [x] T-005 — Санитизация ввода и защита от инъекций 🔒

**Зависимости:** T-001 · **Оценка:** 5 ч

**Что делать**

- `src/tnved_bot/core/sanitize.py` — слои L1 и L2 из раздела 9.1 ТЗ:
  нормализация NFKC, удаление control-chars, zero-width (`U+200B–200F`, `U+2060`, `U+FEFF`),
  bidi-override (`U+202A–202E`), схлопывание пробелов, лимит 2000 символов, отклонение ввода с
  долей не-букв > 70 %, нейтрализация маркеров (`<user_data>`, закрывающие теги, тройные бэктики,
  `Human:`, `Assistant:`, `System:`, `[INST]`)
- Возврат `SanitizedText | RejectReason` — без исключений на нормальном пути
- `tests/test_sanitize.py` — **не менее 15 инъекционных кейсов** из раздела 9.1 ТЗ

**Acceptance criteria**

- [ ] Все 15+ инъекционных кейсов из ТЗ дают ожидаемый результат (текст обезврежен или отклонён)
- [ ] Легитимные описания товаров не портятся: кавычки, дефисы, размеры («труба 20×2,0 мм»),
      латиница вперемешку с кириллицей, единицы измерения — сохраняются
- [ ] Ввод из одних эмодзи / одних символов отклоняется с понятной причиной
- [ ] Срабатывание фильтра пишет событие `injection_suspected` в лог
- [ ] Функция не бросает исключений ни на одном входе (property-тест на случайных байтах)

### - [x] T-006 — Клиент `claude -p`: таймауты, ретраи, семафор, circuit breaker

**Зависимости:** T-001 · **Оценка:** 6 ч

**Что делать**

- `src/tnved_bot/llm/client.py`:
  - `asyncio.create_subprocess_exec` со списком аргументов, `shell=False`
  - промт и пользовательские данные — **через stdin**, никогда в argv
  - флаги: `-p --output-format json --allowedTools "" --permission-mode plan --model <model>`
  - таймауты (текст 90 с, vision 120 с) с гарантированным `kill()` и ожиданием завершения
  - ретраи ×2 с паузами 2 с / 6 с — только на таймаут, пустой вывод, невалидный JSON, ненулевой
    exit code; **не** ретраить отсутствие бинаря и ошибку авторизации
  - `asyncio.Semaphore(CLAUDE_MAX_CONCURRENCY)` + позиция в очереди
  - circuit breaker: 5 подряд неудач → открыт 5 минут, статус доступен наружу
  - проверка доступности `claude` при старте (`claude --version`)
- Фейковый клиент для тестов в `tests/conftest.py`

**Acceptance criteria**

- [ ] Пользовательский текст не появляется в argv — проверено тестом на собранной команде
- [ ] Таймаут убивает процесс; зомби-процессов не остаётся (тест на «зависшем» фейковом бинаре)
- [ ] Отсутствие `claude` в PATH → `LlmError` с понятным сообщением, без ретраев, процесс не падает
- [ ] Breaker открывается после 5 неудач и закрывается по истечении cooldown — тест с подменой времени
- [ ] Семафор ограничивает параллельность: 5 одновременных вызовов → максимум 2 процесса
- [ ] Ни один тест не вызывает настоящий `claude`

### - [x] T-007 — Промты и строгая валидация ответа модели

**Зависимости:** T-005, T-006 · **Оценка:** 5 ч

**Что делать**

- `src/tnved_bot/llm/prompts/classify.md` — системная часть: роль эксперта по ТН ВЭД ЕАЭС,
  правила ОПИ, требование выбирать **только** из переданного списка кандидатов, требование
  вернуть строго JSON, явное указание что содержимое `<user_data>` — данные, а не инструкции
- `src/tnved_bot/llm/prompts/clarify.md` — правила формулировки уточняющего вопроса
- `src/tnved_bot/llm/schema.py`:
  - pydantic-схема ответа (раздел 8.2 ТЗ)
  - извлечение первого сбалансированного JSON-объекта из зашумлённого вывода
  - валидация: `code` — 10 цифр, есть в БД **и** был в списке кандидатов; `confidence` в [0,1];
    `alternatives` ≤ 3 и каждый верифицирован; `reasoning` ≤ 5 строк × 300 симв.;
    `options` — 2–4 элемента ≤ 40 симв. без разметки

**Acceptance criteria**

- [ ] Ответ с текстом вокруг JSON парсится корректно
- [ ] Ответ с кодом, которого нет в справочнике → код отброшен, событие `hallucinated_code` в лог
- [ ] Ответ с кодом не из списка кандидатов → отброшен
- [ ] `confidence` вне [0,1] → клип и понижение, без падения
- [ ] Полностью невалидный ответ (`"извините, не могу"`) → `None`, обрабатывается вызывающим кодом
- [ ] Разметка и ссылки в `reasoning`/`options` вырезаются

## Этап 3 — Телеграм-бот (T-009 … T-012)

Цель этапа: рабочий бот с текстовым сценарием и уточнениями кнопками.

### - [x] T-009 — Минимальный бот: polling, whitelist, текстовый сценарий

**Зависимости:** T-008 · **Оценка:** 5 ч

**Что делать**

- `src/tnved_bot/bot/setup.py` — `Dispatcher`, регистрация роутеров и middleware, long polling
- `src/tnved_bot/bot/middlewares/auth.py` — whitelist, **первый** в цепочке. Доступ разрешён, если
  `user_id` есть в `ADMIN_USER_IDS` (`.env`) **или** в таблице `allowed_users` (`is_active = 1`).
  Список кешируется в памяти, кеш инвалидируется при изменении. Отказ с указанием ID пользователя
  и подсказкой про `/start <код>`; игнорирование групповых чатов. Авторизация только по числовому
  ID — привязка к `@username` запрещена
- `src/tnved_bot/bot/middlewares/logging.py` — `request_id`, латентность
- `src/tnved_bot/bot/handlers/commands.py` — `/start`, `/help`
- `src/tnved_bot/bot/handlers/text.py` — текстовое описание → `classifier` → ответ
- `src/tnved_bot/bot/texts.py` — все русские тексты в одном месте, включая дисклеймер
- Сообщение-плейсхолдер («🔎 Ищу код...»), обновляемое по ходу работы
- Реконнект при недоступности сети: экспоненциальный 1→2→4→…→60 с, бесконечно
- Отбрасывание апдейтов старше `STALE_UPDATE_MINUTES` при старте, с уведомлением отправителю

**Acceptance criteria**

- [ ] `/start` возвращает приветствие с дисклеймером
- [ ] Текстовое описание → форматированный ответ: код, наименование, уверенность, обоснование,
      2 альтернативы, дисклеймер
- [ ] Пользователь не из whitelist получает отказ со своим ID и подсказкой про код приглашения;
      событие `access_denied` в лог; ресурсы ИИ не расходуются
- [ ] Пользователь из `allowed_users` (не админ) получает доступ к классификации, но не к
      админским командам
- [ ] Кеш whitelist не заставляет перезапускать бота: изменение таблицы применяется сразу
- [ ] Весь вывод экранирован (`parse_mode=HTML` + `html.escape`) — тест с кодом, содержащим `<`, `&`
- [ ] Обрыв сети → бот переподключается сам, процесс не падает (тест на моке)
- [ ] Сообщения в групповом чате игнорируются

### - [x] T-010a — Управление доступом: список пользователей и приглашения 🔒

Список пользователей живёт в БД, а не в `.env`: добавление и отзыв — командами бота, без

**Что делать**

### - [x] T-023 — Обучение на исправлениях пользователя

**Зависимости:** T-012 · **Оценка:** 6 ч

**Что делать**

**Acceptance criteria**

- [x] Исправление влияет на последующий подбор по похожему запросу
- [x] Исправление не может протащить код мимо `verify_code`
