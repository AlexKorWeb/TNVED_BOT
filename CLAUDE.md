# TNVED_BOT — Telegram-бот подбора кодов ТН ВЭД ЕАЭС

## Описание

Telegram-бот, который по текстовому описанию товара или по фотографии подбирает 10-значный код
ТН ВЭД ЕАЭС. Работает локально на Windows-машине пользователя, стартует автоматически при
включении компьютера, обращается к ИИ через CLI `claude -p`.

**Ключевой принцип проекта:** ИИ не изобретает коды. Кандидаты берутся из локального официального
справочника ТН ВЭД (SQLite + FTS5), ИИ только выбирает из них, и каждый код на выходе повторно
верифицируется по базе. Код, отсутствующий в номенклатуре, не может попасть в ответ пользователю.

Полное ТЗ: [[docs/TZ|docs/TZ.md]]
Тикеты: [[docs/tasklist/tickets|docs/tasklist/tickets.md]]

## Технический стек

- **Язык:** Python 3.12+ (venv в `.venv`; на машине установлен 3.14 — при конфликте зависимостей
  откатываемся на 3.12)
- **Telegram:** `aiogram` 3.x, long polling (без webhook — работает за NAT)
- **БД:** SQLite + `aiosqlite`, полнотекстовый поиск через FTS5, режим WAL
- **ИИ:** CLI `claude -p` через `asyncio.create_subprocess_exec` (без прямых обращений к API,
  без хранения LLM-ключей)
- **Изображения:** `Pillow` (валидация, ресайз, ре-энкод для снятия EXIF)
- **Планировщик:** `apscheduler` (джанитор фото и сессий)
- **Конфиг:** `pydantic-settings` + `.env`
- **Логи:** `structlog` + `RotatingFileHandler`
- **Тесты:** `pytest`, `pytest-asyncio`
- **Линт/типы:** `ruff`, `mypy`
- **Автозапуск:** Windows Task Scheduler

## Основные договорённости

1. **Активный тикет.** Работа всегда идёт в рамках тикета из `docs/tasklist/tickets.md`.
   Номер активного тикета лежит в `docs/.active_ticket`.
2. **Порядок:** активный тикет → PRD (при необходимости) → план → **подтверждение пользователя**
   → реализация → diff → тесты → коммит.
3. **Без подтверждения не писать код.** Сначала план в `docs/plan/<ticket>.md`, затем ждать «ок».
4. **Малые diff'ы.** Один тикет = один связный коммит. Не смешивать рефакторинг и фичу.
5. **Тесты обязательны** для `core/sanitize.py`, `llm/schema.py`, `core/confidence.py`,
   `db/nomenclature.py`, `storage/photo_store.py`. Перед рефакторингом — проверить наличие тестов
   и прогнать их после каждого изменения.
6. **Не удалять и не перезаписывать файлы** без бэкапа или явного подтверждения пользователя.
7. **Файлы с секретами** (`.env`, `data/tnved.db`) считать read-only — не редактировать без
   явной просьбы.
8. **Ответ пользователю всегда с дисклеймером** о справочном характере классификации.

## Локальное тестирование

- `start_cmd`: `.\.venv\Scripts\python.exe -m tnved_bot` (из корня проекта, `PYTHONPATH=src`)
- `stop_cmd`: `Ctrl+C` в консоли; для фонового запуска — `Stop-Process -Id <PID>`, где PID берётся
  **из `data/bot.pid`**. Не из `data/bot.lock` (пока бот жив, файл залочен и `Get-Content` падает)
  и не из `Start-Process -PassThru` (при перенаправлении вывода PowerShell возвращает PID
  промежуточного процесса — проверено, расходится). Перед убийством проверяй, что `CommandLine`
  процесса содержит `tnved_bot`: после аварийного завершения `bot.pid` устаревает, и номер мог
  достаться другой программе. При штатной остановке `bot.pid` удаляется.
- `smoke_check`: в `logs/bot.log` появляется событие `bot_started` с версией справочника;
  затем в Telegram отправить боту `/start` → получить приветствие, отправить тестовое описание
  («кофеварка капельная бытовая 900 Вт») → получить код `8516 71 000 0` с дисклеймером.
  Автоматическая часть проверки — `python scripts\smoke_check.py`, которая проверяет:
  наличие процесса, доступность `claude` в PATH, активную версию справочника в БД, отсутствие
  `ERROR` в логе за время запуска.
- `required_env`: `BOT_TOKEN`, `ADMIN_USER_IDS` — без них старт невозможен.
  Обычные пользователи в `.env` не перечисляются: они в таблице `allowed_users`, добавляются
  командами бота (`/adduser`, `/invite`) без перезапуска. Остальные переменные имеют дефолты
  (см. `.env.example`).
- `notes`:
  - Docker не нужен. БД создаётся автоматически при первом старте.
  - До импорта справочника (`scripts/import_nomenclature.py`) бот стартует, но на запросы отвечает
    «справочник не загружен» — это ожидаемое поведение, не баг.
  - `claude` должен быть в PATH и авторизован (проверка: `claude --version`).
  - Для теста без реального Telegram-токена используй `pytest tests/test_handlers.py`
    с моком Bot API — не поднимай бота ради unit-проверки.
  - Не запускать вторую копию бота: файловый лок `data/bot.lock` завершит её (код выхода 3,
    запись `already_running` уровня WARNING), но Task Scheduler-задача может уже держать
    процесс — сначала останови её.
  - **`.venv\Scripts\python.exe` на этой машине — стаб-редиректор.** Python установлен как
    `pythoncore-3.12-64` (PEP 514), и venv-обёртка не копирует интерпретатор, а запускает его
    дочерним процессом. Практические следствия, все проверены:
    1. `Start-Process -PassThru` возвращает PID стаба, а не бота — им нельзя пользоваться.
    2. Убийство стаба **не убивает бота** — он продолжает работать и держать polling.
    3. Надёжная остановка — по всем процессам, у которых `CommandLine` содержит `tnved_bot`:
       ```powershell
       Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
         Where-Object { $_.CommandLine -like "*tnved_bot*" } |
         ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
       ```
    4. Это же учесть в T-018: задача планировщика должна останавливать всё дерево процессов.
  - После `Stop-Process -Force` файл `data/bot.pid` остаётся (штатное удаление не отрабатывает).
    Это ожидаемо; лок ОС при этом освобождается сама, ручная уборка не нужна.

Эту секцию читает slash-команда `/local-test` и шаг local-test в `/full-cycle`.

## Workflow — команда агентов

Полный цикл (`/full-cycle`), 8 фаз:

`analyst → researcher → planner → implementer → reviewer → qa → local-test → tech-writer`

- Между фазами — пауза на подтверждение пользователя.
- Шаг **local-test** запускает `/local-test` на машине пользователя после автотестов и до
  tech-writer. Если локальный запуск упал — pipeline останавливается и возвращается к
  `implementer` с логом ошибки. Обойти этот шаг нельзя.

Отдельные команды: `/idea`, `/research`, `/plan`, `/implement`, `/test`, `/local-test`,
`/full-cycle`.

## Запрещено

- Обращаться к `api.anthropic.com` или любому LLM-провайдеру напрямую. Только `claude -p`.
  Если когда-нибудь понадобится HTTP API — только через Cloudflare AI Gateway.
- Хранить `BOT_TOKEN` или любые ключи в коде, в `.env.example`, в логах, в коммитах.
- Собирать SQL-запросы конкатенацией строк. Только параметризованные запросы.
- Вызывать subprocess с `shell=True` или собирать команду конкатенацией.
- Передавать пользовательский текст в аргументах командной строки `claude` — только stdin.
- Отдавать пользователю код ТН ВЭД, не найденный в активной версии `nomenclature`.
- Показывать пользователю stack trace, пути файловой системы, содержимое промтов.
- Логировать полный текст пользователя на уровне INFO (только SHA-256 или усечение до 200 симв.).
- Хранить фото дольше 48 часов.
- Ловить исключения «в пустоту» (`except: pass`) — любое подавление должно логироваться.
- Удалять файлы вне `data/photos`, `data/backups`, `logs` — джанитор обязан проверять путь.
- Добавлять новую зависимость там, где хватает stdlib (см. `.claude/rules/ponytail.md`).

## Безопасность

- **Trust boundary:** всё, что пришло от Telegram, — недоверенные данные. Проходит через
  `core/sanitize.py` до любого другого использования.
- **Prompt-инъекции:** семь слоёв защиты (санитизация → нейтрализация маркеров → изоляция в
  `<user_data>` → `--allowedTools ""` → строгая валидация JSON → экранирование вывода → аудит).
  Детали — раздел 9 [[docs/TZ|ТЗ]]. Любой новый путь ввода обязан проходить эти слои.
- **Whitelist:** доступ разрешён, если `user_id` есть в `ADMIN_USER_IDS` (`.env`) **или** в таблице
  `allowed_users`. Middleware `auth` — первый в цепочке. Авторизация только по числовому ID,
  привязка к `@username` запрещена. Админские команды — только для `ADMIN_USER_IDS`.
- **Коды приглашений:** `secrets.choice`, одноразовые, TTL 24 ч, гашение в той же транзакции,
  что и добавление пользователя (`UPDATE ... WHERE used_by IS NULL`).
- **Фото:** magic-bytes + `Pillow.verify()` + обязательный ре-энкод в JPEG (снимает EXIF и
  polyglot-нагрузку). Имена файлов — только UUID4. Путь проверяется через `Path.resolve()`.
- **Найденная уязвимость** помечается комментарием `# WARNING:` прямо в коде, и сразу же
  предлагается безопасная альтернатива. Небезопасный паттерн не реализуется, даже если о нём
  попросили.
- **Ошибки:** пользователь видит человекочитаемый текст + `error_id`; traceback только в лог.
